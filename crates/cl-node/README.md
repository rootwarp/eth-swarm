# cl-node

The launcher of the eight services (issue #205, Part A). It holds no state and links no service
crate (ADR-001): what it knows about a service is the table in `src/units.rs` (`Service`).

```bash
cl-node units --out <dir> [--network <name>] [--supernode] [--bin-dir <dir>]
cl-node launch --foreground --network <name> [--bin-dir <dir>] [--credentials-dir <dir>]
               [--runtime-dir <dir>] [--ready-timeout <secs>] [--stop-grace <secs>]
```

Exit status: 0 done (launch: stopped by SIGTERM or SIGINT), 1 a failure, 2 a usage error.

## `units`: one systemd unit per service, and `ethswarm.target`

`cl-node units --out <dir>` writes `ethswarm-<svc>.service` for the eight services and
`ethswarm.target`, each through a temporary file and a rename. It refuses, before writing
anything, if a unit's path holds anything but a regular file (a symlink, a directory). The text
is deterministic (no timestamps, fixed key order, one trailing newline), starts with a
"Generated by `cl-node units`. Do not edit" line, and is compared byte for byte with
`tests/golden/` (`UPDATE_GOLDEN=1 cargo test -p cl-node --test units units_golden` rewrites
them). Install them with `install -m 0644 <dir>/* /etc/systemd/system/`, then
`systemctl enable --now ethswarm.target`.

`--network` only names the network in `Description=`; `--bin-dir` is where `ExecStart=` finds
`cl-<svc>` (default `/usr/local/bin`). Both are checked: systemd would expand `%`, `$`, quotes,
backslashes and whitespace in them. `ExecStart=` passes no argument: each service's own config
wiring (cl-verify's command-line flags included) comes with the service mains.

| Service | User = Group | `SupplementaryGroups=` (the sockets it calls, ARCH V-9) | `MemoryMax=` (ARCH §9) | `RestrictAddressFamilies=` | `LoadCredential=` | `StateDirectory=` |
|---|---|---|---|---|---|---|
| cl-verify | ethswarm-verify | – | 512M | AF_UNIX | – | ethswarm-verify |
| cl-engine | ethswarm-engine | – | 256M | AF_UNIX AF_INET AF_INET6 | jwt | – |
| cl-chain | ethswarm-chain | engine p2p verify | 3G, `MemoryHigh=2G`, `MemorySwapMax=0` | AF_UNIX | – | ethswarm-chain |
| cl-store | ethswarm-store | chain | 512M | AF_UNIX | – | – |
| cl-discv5 | ethswarm-discv5 | – | 128M | AF_UNIX AF_INET AF_INET6 | nodekey | ethswarm-discv5 |
| cl-p2p | ethswarm-p2p | chain discv5 store | 768M (supernode: 1536M, `MemoryHigh=1G`) | AF_UNIX AF_INET AF_INET6 AF_NETLINK | nodekey | ethswarm-p2p |
| cl-sync | ethswarm-sync | chain p2p store | 1G | AF_UNIX | – | ethswarm-sync |
| cl-api | ethswarm-api | chain discv5 p2p store sync | 1G | AF_UNIX AF_INET AF_INET6 | – | – |

MemoryMax adds up to 7,296 MiB (8,064 MiB with `--supernode`). Groups are `ethswarm-<svc>`,
sorted. Nothing is in group `ethswarm-api`: its caller is the operator, who adds an account by
hand.

Every unit also has: `Type=notify`, `NotifyAccess=main`, `TimeoutStartSec=90s`,
`TimeoutStopSec=30s`, `Restart=on-failure`, `RestartSec=5s`, `RuntimeDirectory=ethswarm/cl-<svc>`
with `RuntimeDirectoryMode=0750`, `StateDirectoryMode=0700` where it has state, `PartOf=` and
`[Install] WantedBy=ethswarm.target`, and the ops/probe hardening block: `UMask=0077`,
`NoNewPrivileges=yes`, `ProtectSystem=strict`, `ProtectHome=yes`, `PrivateTmp=yes`,
`PrivateDevices=yes`, empty `CapabilityBoundingSet=` and `AmbientCapabilities=`,
`RestrictNamespaces=yes`, `RestrictRealtime=yes`, `RestrictSUIDSGID=yes`, `LockPersonality=yes`,
`MemoryDenyWriteExecute=yes`, `ProtectKernelTunables/KernelModules/KernelLogs/ControlGroups/
Clock/Hostname=yes`, `ProtectProc=invisible`, `ProcSubset=pid`, `SystemCallArchitectures=native`,
`SystemCallFilter=@system-service` and `SystemCallFilter=~@privileged`. `ethswarm.target` has
one `Wants=` per service, in start order, and `WantedBy=multi-user.target`.

### Judgement calls

- **Socket groups.** svc-runtime refuses a socket group that is not the process's primary group
  (a chown would be killed by `~@privileged`). So each service's own group is its socket's
  group, and a caller holds the callee's group as a supplementary group. No UID or GID is shared.
- **cl-sync gets AF_UNIX only.** ARCH lists "cl-sync → providers HTTPS" (the checkpoint fetch),
  but Vera's M4 list gives it no IP, and today's cl-sync service makes no network call. The
  stricter profile wins; `SYNC_ADDRESS_FAMILIES` in `src/units.rs` carries a TODO to add
  `AF_INET AF_INET6` when cl-sync gains its checkpoint fetch.
- **AF_NETLINK for cl-p2p** only: libp2p-tcp watches the interfaces (if-watch) through a netlink
  route socket for its wildcard listen (as in ops/probe).
- **Timeouts.** 90 s to start covers cl-chain's 30 s wait for cl-verify and opening its store;
  30 s to stop covers svc-runtime's 10 s drain and cl-verify's pubkey snapshot flush.
  `RestartSec=5s` stays under systemd's default start limit, so a crash loop keeps retrying.
- **UMask=0077.** ipc sets the socket (0660), its directory (0750) and its lock (0600) modes
  explicitly, and systemd sets the runtime and state directory modes, so nothing needs 0007.
- **StateDirectory** only where ARCH lists state (chain, verify, p2p, discv5, sync), 0700,
  named `ethswarm-<svc>` as in ops/probe (cl-chain's default columns dir is under it).
- **READY=1 only.** Readiness is `sd_notify` READY=1 from the main process. The Hello check
  (cl-node may only call cl-api's `GetHealth`, V-9) is #281.
- **After= only, PartOf= the target.** cl-chain is `After=` cl-verify and cl-engine; cl-store,
  cl-discv5, cl-p2p, cl-sync and cl-api are `After=` cl-chain. No `Requires=`/`BindsTo=`: one
  service's failure never stops another; stopping or restarting `ethswarm.target` reaches all.
- **ProcSubset=pid** is not in Vera's list but is in the ops/probe block the issue asked for.

`crates/cl-node/tests/units-verify.test.sh` runs `systemd-analyze verify` on both profiles and
fails on any diagnostic (verify exits 0 on lines it ignores). CI runs it in the kurtosis-units
job with `ETHSWARM_REQUIRE_SYSTEMD_ANALYZE=1`; elsewhere it uses a user namespace for a private
`/run`, or skips with a notice.

## `launch --foreground`: the services as children (containers)

For a container without systemd. Each child gets what its unit asks of systemd:

- **Order and readiness.** cl-verify → cl-engine → cl-chain → cl-store → cl-discv5 → cl-p2p →
  cl-sync → cl-api. Each gets its own `NOTIFY_SOCKET` (a datagram socket in a 0700 directory of
  its own) and must send `READY=1` within `--ready-timeout` before the next starts. Only a
  datagram whose `SCM_CREDENTIALS` name the child's own pid counts (the units'
  `NotifyAccess=main`).
- **Environment.** Cleared. A child sees `PATH` (systemd's default), `NOTIFY_SOCKET`,
  `RUNTIME_DIRECTORY` (`<runtime-dir>/cl-<svc>`, 0750) and, for cl-engine, cl-p2p and cl-discv5
  only, `CREDENTIALS_DIRECTORY`: a 0700 directory with copies (0400, owned by the child) of its
  own credentials from `--credentials-dir`. A missing credential refuses the launch before
  anything starts. Working directory `/`, umask 0077, and signals as systemd leaves a service:
  none blocked, SIGPIPE ignored, every other disposition the default (cl-node also unblocks its
  own mask, so a SIGTERM always reaches it, whatever started it).
- **Users.** As root, each child drops to its unit's user, group and supplementary groups
  (looked up by name through NSS) before exec. A missing name, or one that resolves to root,
  refuses the launch before anything is created; a failed drop fails the spawn. No child ever
  runs as root. As any other user, the children run as that user (development and tests).
- **Stopping.** Each child leads its own process group. When one exits (before or after
  READY=1) or misses its deadline, or cl-node gets SIGTERM or SIGINT, the running children are
  stopped in reverse start order: SIGTERM to the group, SIGKILL after `--stop-grace`. What an
  exited child left in its group is SIGKILLed before the child is reaped, and every child has
  SIGKILL as its parent-death signal, so nothing outlives cl-node. Exit 0 after a signal, 1
  otherwise.
- **No state.** The sockets and credential copies live in `<runtime-dir>/.cl-node` and go with
  cl-node (one launcher per runtime directory; a directory a killed launcher left is replaced).
  The services' runtime directories stay, as their owners left them.
